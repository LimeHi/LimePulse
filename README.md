# VPN Config Tester Bot

Telegram-бот на aiogram 3.x, который принимает подписку (ссылку, .txt файл
или список ссылок), вытаскивает из неё конфиги (vless / vmess / trojan /
ss / hysteria2), реально проверяет каждый через ядро **sing-box**
(поднимает временный локальный SOCKS-инбаунд на конфиг и стучится через
него на тестовый URL) и присылает рабочие конфиги одним `.txt` файлом —
без пустых строк и лишних пробелов, по одному конфигу на строку.

## Как работает переименование

Для каждого рабочего конфига остаётся оригинальная ссылка целиком,
меняется только `#remark`:

- если в исходном имени конфига был эмодзи-флаг — он сохраняется и
  ставится первым;
- дальше добавляется подпись, которую пользователь указал в диалоге
  (или `/skip`, чтобы обойтись без неё);
- если нет ни флага, ни подписи — используется `config-N`.

## Очередь

Одна подписка = одна "джоба". Джобы обрабатываются по очереди
(`JOB_CONCURRENCY`, по умолчанию 1 одновременно), чтобы не перегружать
сервер запуском десятков процессов sing-box сразу. Внутри одной джобы
конфиги проверяются параллельно, но не больше `TEST_CONCURRENCY` штук
одновременно. Жёсткий лимит на подписку — `MAX_CONFIGS` (по умолчанию 400).

## Переменные окружения

| Переменная         | По умолчанию                              | Смысл |
|--------------------|--------------------------------------------|-------|
| `BOT_TOKEN`        | —                                          | токен бота, обязателен |
| `SINGBOX_BIN`       | `sing-box`                                 | путь к бинарю sing-box |
| `TEST_URL`         | `https://www.gstatic.com/generate_204`     | URL для проверки соединения |
| `TEST_TIMEOUT`      | `8`                                         | таймаут одного теста, сек |
| `TEST_CONCURRENCY`  | `15`                                        | параллельных тестов внутри одной подписки |
| `JOB_CONCURRENCY`   | `1`                                         | параллельных подписок |
| `MAX_CONFIGS`       | `400`                                       | лимит конфигов на подписку |
| `PORT_RANGE_START` / `PORT_RANGE_END` | `20000` / `29999`      | диапазон локальных портов для временных sing-box инстансов |
| `WORK_DIR`          | `/tmp/singbox_jobs`                         | папка для временных конфигов sing-box |

## Запуск локально

```bash
pip install -r requirements.txt
# поставить sing-box: https://sing-box.sagernet.org/installation/
export BOT_TOKEN=xxxx
python main.py
```

## Деплой на Railway

В репозитории есть `Dockerfile`, который ставит сам sing-box (через
Railway Buildpacks поднять бинарь не получится, нужен именно Docker-деплой).
Railway сам подхватит `Dockerfile`, если он лежит в корне репозитория —
дополнительных настроек, кроме переменной `BOT_TOKEN`, не требуется.

Если нужна другая версия ядра, поменяйте `ARG SINGBOX_VERSION` в
Dockerfile.

## Поддерживаемые протоколы

`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`).
Для vless/trojan поддерживаются транспорты `tcp` / `ws` / `grpc` / `http`
и TLS/Reality. Добавить протокол (например `tuic`) — дописать парсер в
`protocol_parser.py` по образцу существующих и зарегистрировать его в
`_SCHEME_PARSERS`.
