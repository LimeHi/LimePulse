# VPN Config Tester Bot

Telegram-бот на aiogram 3.x, который принимает подписку (ссылку, .txt файл
или список ссылок), вытаскивает из неё конфиги (vless / vmess / trojan /
ss / hysteria2), реально проверяет каждый через ядро **sing-box**
(поднимает временный локальный SOCKS-инбаунд на конфиг и стучится через
него на тестовый URL) и присылает рабочие конфиги одним `.txt` файлом —
без пустых строк и лишних пробелов, по одному конфигу на строку.

## Как работает переименование

Для каждого рабочего конфига остаётся оригинальная ссылка целиком,
меняется только `#remark`:

- если в исходном имени конфига был эмодзи-флаг — он сохраняется и
  ставится первым;
- дальше добавляется подпись, которую пользователь указал в диалоге
  (или `/skip`, чтобы обойтись без неё);
- если нет ни флага, ни подписи — используется `config-N`.

## Очередь

Одна подписка = одна "джоба". Джобы обрабатываются по очереди
(`JOB_CONCURRENCY`, по умолчанию 1 одновременно), чтобы не перегружать
сервер запуском десятков процессов sing-box сразу. Внутри одной джобы
конфиги проверяются параллельно, но не больше `TEST_CONCURRENCY` штук
одновременно. Жёсткий лимит на подписку — `MAX_CONFIGS` (по умолчанию 400).

## Переменные окружения

| Переменная         | По умолчанию                              | Смысл |
|--------------------|--------------------------------------------|-------|
| `BOT_TOKEN`        | —                                          | токен бота, обязателен |
| `SINGBOX_BIN`       | `sing-box`                                 | путь к бинарю sing-box |
| `TEST_URL_PRIMARY` | `https://cp.cloudflare.com/generate_204`   | основной URL шага 1 (connectivity), пробуется первым |
| `TEST_URL_VERIFY`  | `https://api.ipify.org?format=json`        | основной URL шага 2 (IP-эхо), пробуется первым |
| `TEST_TIMEOUT`      | `20`                                        | общий таймаут одного запроса, сек |
| `TEST_CONNECT_TIMEOUT` | `10`                                     | таймаут TCP-коннекта, сек |
| `DPI_PROBE_TIMEOUT` | `6`                                          | таймаут отдельной DPI-пробы (голый TCP-туннель без HTTP), сек |
| `MIN_PLAUSIBLE_LATENCY_MS` | `5`                                 | отсечка "слишком быстрого" (подставного) ответа |
| `REQUIRED_VERIFY_MATCHES` | `2`                                  | сколько разных IP-эхо провайдеров должны независимо подтвердить конфиг |
| `STABILITY_RECHECK_DELAY` | `3`                                  | пауза перед повторной проверкой на стабильность, сек (0 — отключить) |
| `SPEEDTEST_URL`    | `https://speed.cloudflare.com/__down?bytes=4000000` | URL для замера скорости |
| `SPEEDTEST_MAX_DURATION` | `6`                                   | макс. длительность замера скорости, сек |
| `MIN_FAST_SPEED_MBPS` | `10`                                     | порог скорости для метки ⚡️ |
| `MAX_FAST_PING_MS` | `80`                                        | порог пинга для метки ⚡️ |
| `TEST_CONCURRENCY`  | `5`                                         | параллельных тестов внутри одной подписки |
| `JOB_CONCURRENCY`   | `1`                                         | параллельных подписок |
| `MAX_CONFIGS`       | `400`                                       | лимит конфигов на подписку |
| `PORT_RANGE_START` / `PORT_RANGE_END` | `20000` / `29999`      | диапазон локальных портов для временных sing-box инстансов |
| `WORK_DIR`          | `/tmp/singbox_jobs`                         | папка для временных конфигов sing-box |
| `TELEGRAM_PROXY_HOST` | —                                         | свой прокси перед api.telegram.org (опционально) |

Проверка конфига состоит из четырёх шагов:

1. **Verify** — конфиг должен получить валидный ответ (реальный IP в
   JSON) минимум от `REQUIRED_VERIFY_MATCHES` РАЗНЫХ провайдеров из
   списка `TEST_URL_PRIMARY` / `TEST_URL_VERIFY` + запасные. Одного
   успешного ответа недостаточно — так отсекаются DPI/block-page,
   которые правдоподобно отвечают на один конкретный домен.
2. **DPI-диагностика** — если verify провалился и НИ ОДИН провайдер не
   ответил вообще ничем (только таймауты/обрывы, ни один HTTP-статус не
   пришёл), это ещё не значит, что сервер мёртв. Бот отдельно поднимает
   голый SOCKS5 TCP-туннель через тот же outbound до одного из тех же
   хостов (порт 443), без единого байта HTTP поверх. Если туннель
   поднимается, а прикладные данные так и не дошли — это классический
   паттерн блокировки протокола по DPI в РФ: сетевое соединение
   технически устанавливается, но полезная нагрузка режется/душится
   сразу после того, как DPI по сигнатуре опознаёт протокол (характерный
   TLS ClientHello, паттерн VMess/Shadowsocks и т.п.). Такой конфиг
   помечается отдельно (`dpi_blocked`) и попадает в сводку бота как
   «похоже заблокировано DPI», а не тонет молча среди обычных «нерабочих».
   Если результат `python_socks` недоступен, этот шаг просто пропускается
   — на остальную проверку это не влияет.
3. **Leak-check** — IP, отданный прокси, сверяется с реальным прямым
   IP сервера (без прокси). Совпадение = трафик по факту не проксировался,
   конфиг бракуется.
4. **Stability recheck** — после успешной верификации бот ждёт
   `STABILITY_RECHECK_DELAY` секунд и делает ещё один запрос через тот
   же прокси, чтобы отсеять ноды, которые рвут соединение почти сразу
   после подключения.

Это делает проверку заметно медленнее одного конфига, но сильно снижает
число ложных срабатываний "рабочий", чем однократный запрос к одному URL,
и вдобавок отличает "сервер недоступен" от "протокол задушен DPI".

## Запуск локально

```bash
pip install -r requirements.txt
# поставить sing-box: https://sing-box.sagernet.org/installation/
export BOT_TOKEN=xxxx
python main.py
```

## Деплой на Railway

В репозитории есть `Dockerfile`, который ставит сам sing-box (через
Railway Buildpacks поднять бинарь не получится, нужен именно Docker-деплой).
Railway сам подхватит `Dockerfile`, если он лежит в корне репозитория —
дополнительных настроек, кроме переменной `BOT_TOKEN`, не требуется.

Если нужна другая версия ядра, поменяйте `ARG SINGBOX_VERSION` в
Dockerfile.

## Поддерживаемые протоколы

`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`).
Для vless/trojan поддерживаются транспорты `tcp` / `ws` / `grpc` / `http`
и TLS/Reality, включая `allowInsecure=1` / `insecure=1` (самоподписанные
сертификаты). Добавить протокол (например `tuic`) — дописать парсер в
`protocol_parser.py` по образцу существующих и зарегистрировать его в
`_SCHEME_PARSERS`.

Ограничение: `ss://` со SIP003-плагином (`?plugin=obfs-local...`,
`v2ray-plugin` и т.п.) не поддерживается — в образе нет бинарников
плагинов, такие ссылки отбрасываются на этапе разбора, а не тихо
проверяются "как есть" без обфускации.
